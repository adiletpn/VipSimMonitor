# VIP SIM Monitor

Асинхронный монитор красивых («блатных») номеров на витринах Tele2, Altel, Activ/Kcell и Beeline (Казахстан).
Каждый новый номер оценивается движком `scorer.py`, а улов прилетает карточкой в Telegram с кнопкой «⚡ ЗАБРАТЬ НОМЕР СЕЙЧАС».

Стек: `asyncio` + `aiohttp` + `aiosqlite`. Telegram Bot API вызывается напрямую (`tg.py`), без aiogram и pydantic. Поэтому процесс занимает около 40–60 МБ, а не 160.

## Структура

| Файл | Назначение |
|---|---|
| `main.py` | Точка входа: парсеры, очередь уведомлений, бот, обслуживание, graceful shutdown |
| `config.py` | Переменные окружения + динамические настройки из SQLite, импорт cURL |
| `scorer.py` | Оценка красоты номера: 4 группы правил, итог не больше 100 |
| `database.py` | SQLite в режиме WAL: дедупликация, уловы, статистика, настройки, автоочистка через 30 дней |
| `notifier.py` | Приоритетная очередь (сначала бесплатные), защита от флуд-лимитов, пауза 0,7 с |
| `bot.py` | Админ-панель (только для `ADMIN_CHAT_ID`) |
| `parsers/` | `base_parser.py` (анти-бан, Circuit Breaker, универсальный разбор JSON) и адаптеры операторов |

## Анти-бан

- Паузы между запросами к одному оператору: 20–35 с; в режиме `/turbo` — 10–15 с; с 01:00 до 05:00 по Астане — 45–60 с. Если турбо включён вручную, он важнее ночного режима.
- У каждого оператора своя сессия и свои cookies, а User-Agent не меняется до перезапуска. В запросах уходят полные браузерные заголовки: `Accept-Language: ru-RU,ru;q=0.9,kk;q=0.8`, `Origin`, `Referer` и `Sec-Fetch-*`.
- `refresh_session()` раз в 45 минут делает GET на главную страницу витрины.
- Circuit Breaker: при ответе 403/429 или после трёх сетевых ошибок подряд парсер этого оператора засыпает на 5–10 минут (учитывается `Retry-After`). Остальные операторы и бот продолжают работать.
- `PROXY_URL`: если задан, все запросы к операторам идут через этот прокси.

## Как работают адаптеры

**Tele2 и Altel настроены из коробки.** Оба работают на одной платформе eshop, адреса найдены в JS их магазинов:

- список номеров: `GET https://<tele2|altel>.kz/eshop/catalog/numbers?prefix=…&category=-1&mask=…`;
- обязательные заголовки: `operatorType: TELE2` или `ALTEL`, `clientType: WEB`, `platform: web`;
- `category=-1` — свободные номера за 0 ₸; цены остальных категорий приходят из `/eshop/catalog/numbers/categories`;
- без `prefix` API отдаёт пустой список, за один ответ — не больше 100 номеров;
- парсер перебирает префиксы (Tele2: 707, 747; Altel: 700, 708) и 20 масок.

- выдача случайная и зависит от города: на каждый запрос подставляется случайный из 22 городов (`city`);
- кнопка в карточке ведёт прямо на оформление номера: `/eshop/sim-web/ru/checkout?phone=…&price=…`.

**Activ/Kcell** тоже настроен из коробки. У них общий бэкенд и общий пул номеров:

- список номеров: `POST https://www.activ.kz/api/v1/camunda-workers/external/reservation-list?page=0&size=100` с телом `{"msisdnCategories":["REGULAR"],"phoneNumbers":[]}` (или `BRONZE`);
- бесплатных номеров нет; бот смотрит «Простой» (REGULAR, 500 ₸) и «Бронзу» (BRONZE, 5 500 ₸, в ней много зеркальных номеров). Остальные классы: Серебро 10 500, Золото 50 500, Платина 100 500 ₸;
- выдача случайная, а поиск по маске сервер не поддерживает.

**Beeline не подключён.** Продажа номеров переехала из веб-магазина в приложение Janymda, веб-API больше нет.

Для любого другого запроса (например, если поменяется API) скопируйте его из DevTools (cURL или JSON) и отправьте `/update_auth`. Адаптер подставляет в запрос:

- `{prefix}` — префикс из списка `prefixes`;
- `{mask}` — поисковую маску из списка `masks`;
- `{page}` / `{offset}` / `{size}` — параметры пагинации.

При импорте cURL плейсхолдеры расставляются сами: поля `page`, `pageNumber`, `offset`, `mask`, `pattern`, `search`, `query` и похожие.

Ответ разбирается универсально. В JSON любой вложенности находятся номера (`+7…`, `8…`, 10 цифр с мобильным кодом Казахстана) и цена (`price`, `cost`, `amount`, `isFree`; `oldPrice` и скидки пропускаются). Если ответ не JSON, номера ищутся регулярным выражением в HTML.

## Оценка номера

Баллов нет. Номер оценивается так, как его видит человек: `+7 КОД БЛОК-ПАРА-ПАРА`. Правила настроены по тестам вкуса владельца.

| Уровень | Что делает бот | Примеры |
|---|---|---|
| 🔥🔥 ЖИР | присылает сразу (не больше 5 карточек в час, остальное — одним списком) | блок наоборот кода или в ритм коду + тройка в хвосте: `708 807-29-99`, `708 808-11-14`; хвост `77-77`; всего две цифры после кода; лесенка `123-45-67`; блок-лесенка + хвост-лесенка `987-12-34` |
| 🔥🔥 ЖИР в VIP 14 500 ₸ | присылает сразу, но только то, чего не бывает в Cool: хвост `47-47`, `00-88`, `77-77` **плюс** хвост из цифр кода или блок под код | `747 873-47-47`, `747 912-74-74`, `708 482-00-88`. А `708 807-29-99` в VIP — просто 🔥: в Cool такое есть за 4 500 ₸ |
| 🔥 ТОП | только разделы и итог дня | один признак: тройка `891-88-85` или блок `708 807` |
| 💎 КРАСИВЫЙ | только разделы | повтор пар `45-45`, две двойки `11-22` |

Где бот ищет: Cool 4 500 ₸ (Tele2 и Altel, полный перебор масками `00`–`99`) и «Бронза» Activ/Kcell 5 500 ₸. VIP 14 500 ₸ выключен по решению владельца; правило для него (строка выше) осталось в коде, если захочется вернуть. Разбор показал, сколько там ЖИРа: в 43 тысячах номеров Cool — 1, в 6 тысячах номеров VIP — 6. Бесплатные и «Простой» Activ не проверяются: там ничего подходящего нет.

## Команды бота

В меню бота одна кнопка — «📊 Статус». Остальные команды скрыты и нужны только для тонкой настройки.


| Команда | Что делает |
|---|---|
| `/start` | Меню с кнопками |
| `/status` | Состояние каждого оператора |
| `/stats` | Статистика за сегодня и за всё время, топ-3 улова |
| `/live` | Включает или выключает тихий пульс раз в 15 минут |
| `/score 65` | Меняет порог баллов (значение сохраняется в БД) |
| `/turbo` | Турбо-охота на 1 час |
| `/update_auth <op> <cURL или JSON>` | Обновляет запрос, заголовки или cookies без деплоя |
| `/backup` | Присылает файл SQLite |
| `/test [номера…]` | Прогоняет номера через скорер |

## Шаг 1. Залить код в `adiletpn/VipSimMonitor`

1. Создайте на GitHub пустой репозиторий `VipSimMonitor`, лучше приватный. README добавлять не нужно.
2. В папке проекта выполните:

```bash
git init
git add .
git commit -m "VIP SIM Monitor"
git branch -M main
git remote add origin https://github.com/adiletpn/VipSimMonitor.git
git push -u origin main
```

## Шаг 2. Скопировать API-запросы операторов из DevTools (≈2 минуты на оператора)

1. Откройте в Chrome страницу выбора номера у оператора (раздел «Выбрать номер», «Красивые номера» или покупка eSIM).
2. Нажмите **F12**, откройте вкладку **Network** и включите фильтр **Fetch/XHR**.
3. Введите на сайте маску поиска (например, `777`) или перейдите на следующую страницу списка.
4. В списке запросов найдите тот, у которого во вкладке **Preview** виден массив номеров.
5. Кликните по нему правой кнопкой и выберите **Copy → Copy as cURL (bash)**.
6. Отправьте боту сообщение:
   ```
   /update_auth tele2 curl 'https://…' -H '…' --data-raw '…'
   ```
   Если cURL длиннее 4096 символов, сохраните его в `.txt` и отправьте файлом с подписью `/update_auth tele2`.
7. Бот удалит ваше сообщение (в нём cookies) и ответит, какие плейсхолдеры нашёл. Если `{mask}` или `{page}` не определились, допишите их вручную:
   ```
   /update_auth tele2 {"payload": {"searchText": "{mask}", "page": "{page}"}, "pages": 5, "page_start": 1}
   ```
8. Повторите для `altel`, `activ` и `beeline`.

Когда cookies протухнут (в `/status` появится 401/403 или «пустой ответ»), обновите их без деплоя. Можно заново отправить cURL или прислать только cookies:

```
/update_auth beeline {"cookies": {"session": "…"}}
```

Другие полезные команды:

- `{"masks": ["", "777", "000", "1234"]}` — поменять список масок;
- `{"enabled": false}` — отключить оператора;
- `{"shop_url": "https://…"}` — поменять ссылку на кнопке.

## Шаг 3. Railway

1. **New Project → Deploy from GitHub repo** → выберите `adiletpn/VipSimMonitor`. Railway возьмёт процесс `worker` из `Procfile`.
2. **Volume:** в сервисе выберите **Settings → Volumes → Add Volume**, Mount path `/data`. Без него БД будет создаваться в `./vip_sim.db`, и настройки будут теряться при каждом редеплое.
3. **Variables:**

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | токен от @BotFather (обязательно) |
| `ADMIN_CHAT_ID` | ваш chat id, можно узнать у @userinfobot (обязательно) |
| `DB_PATH` | `/data/vip_sim.db` |
| `MIN_SCORE` | `45` (см. раздел о частоте уловов ниже) |
| `MAX_PRICE` | `3000` |
| `PROXY_URL` | необязательно, например `http://user:pass@1.2.3.4:8080` |
| `PYTHONUNBUFFERED` | `1` |
| `MALLOC_ARENA_MAX` | `2` (снижает потребление RAM в glibc) |
| `RAILWAY_DEPLOYMENT_OVERLAP_SECONDS` | `0` (старый инстанс гасится до старта нового, поэтому нет `Conflict: getUpdates`) |
| `RAILWAY_DEPLOYMENT_DRAINING_SECONDS` | `15` (время на graceful shutdown после SIGTERM) |

Запросы операторов можно задать и через переменные окружения вместо `/update_auth`. Используются префиксы `TELE2_`, `ALTEL_`, `ACTIV_` и `BEELINE_`:

- `_URL`, `_METHOD` — адрес и метод запроса;
- `_HEADERS`, `_PAYLOAD`, `_PARAMS` — JSON;
- `_COOKIES` — JSON или строка `a=1; b=2`;
- `_MASKS` — список через запятую;
- `_PAGES`, `_PAGE_START`, `_PAGE_SIZE` — пагинация;
- `_WARMUP_URL`, `_SHOP_URL`, `_ENABLED` — прочее.

Настройки, сохранённые через бота, важнее переменных окружения.

4. Нажмите Deploy. В Telegram придёт сообщение «🟢 VIP SIM Monitor запущен». Затем отправьте боту `/start` и `/test`.

## Сколько будет уловов

На случайных номерах с весами из ТЗ порог 45 проходит примерно 5,5% номеров, 65 — примерно 2,3%, 90 — примерно 0,65%. При первом проходе по большой базе это может дать сотни уведомлений. Очередь их выдержит (300 сообщений, пауза 0,7 с), но читать будет неудобно. Если уведомлений много, поставьте `/score 65`.

## Ограничения

- В панели RAM показывает **пик** RSS (`ru_maxrss`), а не текущее значение.
- Реальное потребление на Railway — около 35–42 МБ RAM (бот без aiogram), это укладывается в лимит 45–55 МБ.
- Частый автоматический опрос сайта может нарушать пользовательское соглашение оператора. Паузы по умолчанию щадящие, их не стоит сокращать сильнее, чем делает `/turbo`.
